The installed app opened, saved drafts, exported Letter PDFs, and retained invoice 2060 after restart. The updater is configured with the public key and intended `foodcel/invoice-company-app` feed. ## Prerequisites and first package

- **Build PC:** Build on Windows. Install Microsoft C++ Build Tools with **Desktop development with C++**, Rust via `rustup` with the Windows **MSVC** toolchain, and the WebView2 Runtime if absent. For Tauri **2.12**, use Rust **1.90 or newer**. Node.js LTS is needed only if the chosen frontend uses the JavaScript toolchain; then add the Tauri 2 CLI to that project. Building **MSI** also needs Windows' **VBSCRIPT** optional feature enabled (normally on; check it if WiX `light.exe` fails). [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/), [Tauri 2.12 release](https://v2.tauri.app/blog/tauri-2.12/), [Tauri CLI](https://v2.tauri.app/reference/cli/).
- **Dad's PC:** It needs a supported Windows version, the matching app architecture, and WebView2 Runtime; it does **not** need Rust, Node, or the C++ build tools to run an installed app. The actual OS, CPU architecture, WebView2 state, internet access, and admin rights remain unverified. Tauri 2.12 dropped official Windows 7 support, despite older installer guidance still describing it. Target Windows 10/11 unless Dad's actual machine calls for another supported configuration. [Tauri 2.12 release](https://v2.tauri.app/blog/tauri-2.12/), [Microsoft WebView2 distribution](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution).
- **Package:** Once a working Tauri 2 project exists, set a stable app identifier/product name, increasing app version, `bundle.active: true`, and `bundle.targets: "nsis"` or `"msi"`; run `npm run tauri build` if using Tauri's npm project script. Tauri puts the setup `.exe` under the release bundle's `nsis/` directory or the `.msi` under `msi/`. **NSIS** is the recommended first Dad PC package: its default `currentUser` install goes to `%LOCALAPPDATA%` without administrator rights. `perMachine` installs to Program Files and needs elevation; `both` also asks for elevation. **MSI** is built with WiX Toolset v3 on Windows; if selected, fix `bundle.windows.wix.upgradeCode` before the first release so later versions replace the same app. [Tauri Windows installer](https://v2.tauri.app/distribute/windows-installer/), [Tauri configuration](https://v2.tauri.app/reference/config/).

## WebView2 and signatures

- Tauri renders with WebView2. The default installer mode, `downloadBootstrapper`, checks for the runtime and downloads/executes Microsoft's bootstrapper when needed; a machine missing WebView2 then needs internet. Windows 11 includes Evergreen WebView2 and most Windows 10 machines have it, but its presence still needs checking. For an offline Dad PC, use `bundle.windows.webviewInstallMode: { "type": "offlineInstaller" }` (about **127 MB** extra). `fixedRuntime` is about **180 MB** extra and requires shipping runtime updates with the app; `skip` can leave the app unable to run. [Tauri WebView2 installer modes](https://v2.tauri.app/distribute/windows-installer/#webview2-installation-options), [Microsoft WebView2 distribution](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution).
- **Updater signing is mandatory and separate from Windows code signing.** Generate one Tauri updater key pair with `tauri signer generate`; put the **public-key content**, not its path, in `plugins.updater.pubkey`. Keep the private key backed up and outside the repository. At build time set `TAURI_SIGNING_PRIVATE_KEY` to its path or content and, if encrypted, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` in the process environment (`.env` is insufficient). Set `bundle.createUpdaterArtifacts: true`; Tauri 2 then emits the Windows installer **and its `.sig`**. Losing the private key prevents updates to existing installs that trust its public key. [Tauri updater: signing and artifacts](https://v2.tauri.app/plugin/updater/#signing-updates).
- **Windows Authenticode signing** uses a code-signing certificate or signing service and Tauri's Windows signing settings; it is **not** the updater key. An unsigned package can be installed locally but can show a Microsoft SmartScreen warning when downloaded. Signing is a pending distribution choice, and even a newly signed release may still show a reputation warning. [Tauri Windows code signing](https://v2.tauri.app/distribute/sign/windows/).

## Future updates and local proof

- Add `tauri-plugin-updater` and an app-side call to **check, download, and install** updates (for example at launch or from an Update action). This is a client check against a release endpoint, not a remote push into a closed app. In production, `plugins.updater.endpoints` must be reachable **HTTPS** URLs. A static JSON feed needs `version` plus `platforms.windows-x86_64.url` and `platforms.windows-x86_64.signature` for an x64 build; `signature` is the **contents** of that build's `.sig`, not a link. A dynamic server instead returns **204** for no update or **200** with `version`, `url`, and signature. Windows closes the app before installing; updater `installMode: "passive"` is the default. Host both the signed installer and feed when releases begin. [Tauri updater configuration, server formats, and Windows install mode](https://v2.tauri.app/plugin/updater/).
- **Can be proved locally without publishing:** after scaffolding, build an unsigned NSIS/MSI installer; install, launch, uninstall, and check WebView2 behavior on a clean Windows test machine. For update proof, build and install version A, build higher version B with the **same updater key**, serve B's installer plus matching signature/feed from a local endpoint, then run the app's update check and verify installation, version, relaunch, and saved drafts. A loopback HTTP feed needs Tauri's `dangerousInsecureTransportProtocol: true` **only in an isolated test configuration**; production endpoints require HTTPS. Also test no update, bad signature rejection, and a machine with missing WebView2 or no network. No public host, Git repository, or Windows certificate is needed for these local checks, but the updater key is. [Tauri updater](https://v2.tauri.app/plugin/updater/), [Tauri Windows installer](https://v2.tauri.app/distribute/windows-installer/).
