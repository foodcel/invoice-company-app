# Windows app integration contract

## Current workflow amendments (0.1.32)

These amendments supersede older descriptions in this contract. Approved work mockup 2 uses description above centered field labels and number / unit price / quantity / amount below. Work-description stars queue FIFO improvements and apply them automatically; the existing proposal workflow remains for notes and line dictation. Automatic proofreading runs after edited multiline writing fields lose focus. One top Undo removes all AI-origin corrections, cancels the queue, and retains manual edits. PDF, Print and Send wait for current corrections and queued jobs, rejecting stale results and preserving source text on failures. Print only prints without archiving or issuing a number; Save Draft remains editable persistence only. Work pages repeat identity information and the final page contains the full summary; no per-page subtotal appears. Editable legacy tax decisions migrate to automatic province detection without an extra Québec confirmation; explicit manual selections and archived PDFs remain intact.

The selected `mockups/index.html` is the visual source. `app/web/` is the Vite input, `app/dist/` is its bundled output, and `app/src-tauri/` is the local Windows host. The app works without a server for document entry, storage, printing and PDF creation. French is the default language. Do not add customer facts or work details that Dad did not enter.

The header AI button explicitly proofreads project/client/address/shipTo, every description and every client note through the existing correction manager, using field-specific instructions and rejecting stale results. It preserves financial/date/contact fields and shares manual-preserving Undo. Clicking Soumission on an issued invoice uses `create_quote_from_invoice` after flushing edits; reopening the source via Undo never modifies archived invoice history.

## Draft JSON

Use the mockup's field names: `id`, `kind` (`soumission` or `facture`), `date`, `validUntil`, `dueDate`, `client`, `shipTo`, `address`, `contact`, `email`, `project`, `notes`, `deposit`, and `items` (`description`, `quantity`, `price`). Date strings are `YYYY-MM-DD`; text fields remain strings. `englishCopy` holds the English project, notes, and line descriptions plus their exact French source texts; changing those French texts makes the English copy stale. It is saved and backed up with the same draft and never replaces French fields. The copy becomes reviewed when the user creates its English PDF after viewing the preview. Printing uses the viewed translation without changing the stored review state. `invoiceNumber` is a displayed number supplied by the backend. `issuedNumber` is `null` until the first successful invoice export and stays fixed thereafter. The UI must never advance invoice numbering on draft save or repeated export. Print uses an in-memory document and never archives a PDF, assigns issuedNumber or advances the cursor, whether printing completes, fails or is cancelled. Only a successful archive issues the invoice number. The backend is the authority for `invoiceNumber` and `issuedNumber`.

`payments` is an ordered array of `{ amount, date }` strings. A date may be empty or a valid `YYYY-MM-DD`; a filled payment must have a finite nonnegative amount. Empty rows are editable placeholders and do not print. Older drafts, recovery versions, and pending export snapshots without this array migrate their scalar `deposit` to one undated row; an explicit empty array remains empty. `deposit` remains a compatibility mirror; `payments` is authoritative when present. The sum uses cent rounding per row and is deducted after tax. Both customer languages preserve dates and amounts, show each positive row, the combined total, and the remaining balance; long lists flow onto additional Letter pages.

Client notes use `noteEntries`, an ordered array of strings (`note_entries: Option<Vec<String>>` in Rust). Each entry may contain multiple lines. Missing or null entries migrate the entire legacy `notes` scalar to one entry without trimming or splitting paragraphs; fresh drafts start with `[""]`, and an explicit `[]` stays empty. Entries are authoritative when present. The compatibility `notes` mirror joins all entries except exact empty strings with `\n\n`; whitespace-only strings and internal blank lines remain exact. Saves/exports reject a mismatched mirror, invalid controls (except LF/CR/tab), more than 500 entries, or more than 50,000 UTF-8 bytes in the mirror including separators; nothing is truncated or silently overwritten. Migration covers current records, autosave recovery, durable saved versions, archived snapshots, and pending exports, and rewrites valid primary/backup copies without changing generation. Legacy promoted recovery IDs remain valid only when their exact single-entry scalar identity is preserved. English translation and staleness continue to use the exact `notes` mirror; French entries never get replaced with translated text. `web/client-notes.js` exports `noteRows(draft)` (copied rows or one exact legacy scalar), `setNoteRows(draft, rows)` (validate, copy, mutate entries and mirror, return draft), `normalizeNoteRows(draft)` (same normalization in place), `notesMirror(rows)`, `noteIssues(draft)`, `MAX_NOTE_ENTRIES`, and `MAX_NOTES_BYTES`. The frontend supplies at least one empty editable row when needed. Accepted document dictation replaces eligible notes with one extracted entry and synchronizes the mirror; manual/nonempty notes remain protected.

## Native commands

All document state responses include `currentPdfPath`, the latest archived PDF path for the current record or `null`. This path does not imply that the current edited/restored Draft matches that archive. Records include `savedVersions` (durable restoration history) and `sentAt` (latest associated Microsoft acceptance timestamp or `null`). Each export includes `snapshot: Draft | null` and `sentReceipts: [{ attemptId, senderEmail, acceptedAt }]`. New archives persist the full editable snapshot; legacy archives are not reconstructed from current content. Receipt timestamps mean accepted for processing, not delivered. Empty receipt history means unknown/no locally associated acceptance, not verified unsent. `sentAt` describes archived sends for the record, not the current Draft. Association is saved after successful `send_outlook_mail`; failure after acceptance reports the need to check Outlook before another attempt. Existing Outlook journals lack document/path binding and cannot be reliably backfilled. Restoring versions preserves all archive entries and receipts.

- `load_state() -> { current, records, nextInvoiceNumber, pdfDirectory, usingDefaultDirectory, invoicePdfDirectory, quotePdfDirectory, usingDefaultInvoiceDirectory, usingDefaultQuoteDirectory }`: load the current draft, searchable recent records, and PDF destinations. `pdfDirectory` is the current document's destination. A record contains `{ id, draft, updatedAt, exports }`. A fresh install uses `Documents/Entreprise/Factures` and `Documents/Entreprise/Soumissions`. Older installations retain their original shared destination until a type-specific selection is made; configuring one preserves the other's old choice.
- `save_draft({ draft }) -> { current, records, nextInvoiceNumber }`: atomically persist the editable draft. The backend preserves any existing `issuedNumber`, and returns its authoritative invoice number. Trigger after a short typing pause and on field blur/structural changes.
- `new_draft({ kind }) -> { current, records, nextInvoiceNumber }`: create a separate persistent UUID and make its blank draft current; existing records remain. The frontend must flush unsaved fields first because this command does not receive or save frontend-only edits. Project/client are persisted names for draft display/search; no separate draft-title field exists.
- `create_quote_from_invoice({ id }) -> StateResponse`: atomically clone the current saved issued invoice into a new quotation UUID with no invoice number, English copy or export history. Preserve customer/work/payment details and initialize missing validity to the document date +30 days. Preserve the source record, versions, archived PDF bytes, numbering cursor and output folders. Reject stale/non-issued/non-invoice sources, pending exports and record-capacity overflow without writing state.
- `open_draft({ id }) -> { current, records, nextInvoiceNumber }`: make a recent draft current.
- `delete_draft({ id, expectedDraft }) -> StateResponse`: after a named UI confirmation, atomically remove only that unissued record and its draft recovery history. Reject any registered PDF export, issued current/historical snapshot, pending export, missing ID or changed expected draft. Preserve PDF files, invoice cursor, folders and other records. Deleting the open record creates a blank current document of the same type; deleting another record leaves the current draft unchanged. The library remains open after success. Frontend must flush unsaved edits and recheck confirmation content first; native equality/protection checks remain authoritative.
- `export_pdf({ draft, pdfBytes, expectedInvoiceNumber, language }) -> { path, filename, nameCollision, invoiceNumber, snapshot }`: validate and atomically write the completed PDF to the folder selected for its document type. New installations default to `Documents/Entreprise/Factures/` and `Documents/Entreprise/Soumissions/`; existing installations retain their shared folder until separate folders are configured. Use an automatic safe name. `pdfBytes` is an array of unsigned bytes. For invoices, reject stale `expectedInvoiceNumber`; issue the number only after a successful file write, then keep it on all later exports of that document. Quotes have no public number. Repeated exports of one document retain its number and use a collision-safe file path; `nameCollision` tells the UI when the original filename was already occupied. Return a new snapshot. `language` is `fr` or `en`. If a custom folder disappears, report an error and do not issue a number or silently redirect output.
- `restore_previous({ id }) -> { current, records, nextInvoiceNumber }`: restore a recoverable earlier version of a record without changing an already issued invoice number.
- `load_document_versions({ id }) -> [{ id, type, draft, createdAt, filename, path, language, restorable }]`: list saved PDF exports and edit/restoration history. `type` is `export` or `recovery`; `draft` is the full editable snapshot or `null` for legacy archives lacking one. Null snapshots are view-only. `createdAt` is null for old autosave recovery with no recorded timestamp. Version IDs are opaque, bound to the document and exact snapshot, never array indices. Current editable content is in the state response.
- `restore_document_version({ id, versionId }) -> StateResponse`: restore that selected snapshot into the same current editable record, preserve the displaced current draft and selected version in history, and retain backend-owned issued number/reuse metadata. Unissued restorations use the current automatic cursor and require fresh reuse confirmation where applicable. Reject unknown, stale, cross-document, view-only versions and unresolved pending exports. Do not overwrite/delete a PDF, change numbering/folders, or send mail. History capacity errors fail without pruning old entries.
- `read_document_pdf({ id, path }) -> number[]`: return native archived PDF bytes only for an exact registered export path belonging to that document. Limit reads to the PDF size bound, validate PDF framing, and verify the recorded SHA-256 when available. Legacy hashless PDFs remain viewable without a claim of historical integrity.
- `set_next_invoice_number({ number, allowReuse })`: persist the chosen automatic starting point, including a backward reset. Older/already-issued numbers require a warning and `allowReuse: true`. Unissued drafts follow the new cursor across restart and kind switches. If the current invoice is issued, start a new blank invoice. Preserve all issued numbers and PDF files. The first successful archive advances from the selected cursor; repeated exports do not advance it. The explicit `invoiceSequenceReset` flag allows history above the cursor without relaxing validation of legacy stores or unacknowledged duplicate issuance.
- `confirm_invoice_number_reuse({ draftId, expectedNumber })`: acknowledge a reused number for one unissued invoice after visible confirmation, without resetting the cursor. Reject stale numbers and issued/non-invoice documents. PDF/email export checks reuse before writing any file; Print does not reserve or confirm a number; automatic cursors reaching old numbers require confirmation again.
- `set_output_directory({ path, kind })`: choose an existing writable absolute destination independently for `facture` or `soumission`, or pass `null` to restore that type's default. All archival paths, including email, route by kind. Printing has no archival path. Older PDFs stay in place and remain registered for attachments. Pending exports recover in the folder belonging to their snapshot kind; resolve them before changing destinations.
- `get_ai_settings()` and `set_ai_provider({ provider })`: select only `chatgpt` or `business`; return `chatgptConfigured`, `businessConfigured`, `authPending`, `authError`, never credentials. Legacy `openai`/`zai` persisted values migrate to `chatgpt` without losing draft content. `set_ai_key({ provider, key })` accepts only Business subscription access tokens, with `key: null` removing that token. Personal subscription login uses `start_chatgpt_login`, `open_chatgpt_login`, `cancel_chatgpt_login`, and `disconnect_chatgpt`. Only an opaque attempt ID is returned to the renderer; the native code retains and opens the matching authorization URL. No metered API adapter or fallback exists.
- `ai_translate_english({ draft }) -> { project, notes, descriptions }`: use the selected provider to translate only customer-entered free text. Require that the submitted draft matches the saved document; reject missing keys, provider errors, malformed responses, and changed line counts without replacing French data. The UI saves the translated copy with the French draft and shows it in the English preview. Creating or printing the English PDF confirms that copy.
- `start_local_asr() -> websocketUrl`: start the bundled Nemotron 3.5 CPU speech engine on an authenticated loopback port. The WebView streams 16 kHz PCM to it, renders partial transcript events, and commits final utterances. Audio is not uploaded to OpenAI or Z.ai.
- `ai_rewrite_line({ source, style, variation }) -> string`: request French prose or bullet text for a single line. The UI shows a proposal and changes the original line only after acceptance.
- `ai_extract_document({ transcript }) -> VoiceUpdate`: extract optional fields and ordered work items from cumulative recognized speech. The frontend validates dates and amounts, retains existing values, and saves accepted field updates as an ordinary draft. This command cannot export a PDF or issue a number.

All commands return clear errors without replacing the last good saved data. The backend owns the local data file and a separate recoverable backup. Do not put secrets or customer data in the repository.

## UI and PDF module

The header save icon reports autosave state and can manually save the current document. The separate bottom Enregistrer le brouillon action saves the same record into Documents and stays on it; it does not duplicate the record, export a PDF, issue a number or send mail. Creating another document from Documents keeps all prior drafts available. Modal overlays own scrolling and preserve/restore the underlying app position; hidden app scrollbars do not disable ordinary scrolling.

`app/web/pdf.js` exports `createPdf(draft, { invoiceNumber, language }) -> Promise<Uint8Array>`. The approved compact layout uses a 38.4pt logo aligned with the company wordmark, content-aware address cards (88pt minimum), and a tighter recap (164pt minimum with payments, 125pt without). Body fonts and all customer facts remain unchanged. It renders a US Letter customer PDF with company logo, real-text company name/address/phone, item descriptions with wrapping and multiple pages as needed, totals, deposit if present, and the confirmed TPS/TVQ registration numbers. Work descriptions are justified to the description column width on wrapped nonfinal paragraph lines; explicit breaks, paragraph endings and short single-line descriptions stay naturally spaced. Word spacing is reset before quantities and monetary fields. It must encode the supplied client data without HTML execution. English output takes a reviewed overlay; the renderer does not translate. The backend verifies current review before saving an English PDF. `app/web/app.js` imports this function and invokes `export_pdf` only after field validation. Print prepares the customer document in memory and opens printing only; it never calls export_pdf. Ordinary draft autosave remains separate. Cancelling the print dialog does not issue a number or add a history entry.

Documents search starts as an icon, expands into a focused input with icon/count filters, and clears the query while preserving the type when closed. Search transitions animate only on explicit opening/closing and honor reduced motion. The Documents panel has no footer; its compact Nouveau header control creates either draft type. Settings and scrollbar isolation must work with normal and reduced motion in the combined production stylesheet. Previous Versions displays the selected archived PDF or saved draft inline; only the main document library has a separate review-before-opening dialog.

The packaged UI should keep the mockup's single selected design, including the two large document choices, side-by-side editor and large preview, light/dark modes, date picker, multiline work lines, line mic/AI icons, recent documents, Undo, and validation. Manual French entry and export remain fully available offline. Translation requires an explicitly chosen provider; English PDF creation requires the user to review its preview, then confirm through Create PDF. Print uses the reviewed preview text without archiving it. Work-line dictation and rewriting are reviewable proposals. Document dictation shows interim words locally, then passes completed utterances to the selected text AI to update fields, preserves existing manually entered values, and clearly asks for review before PDF export. Recognized words must remain visible for retry or copying if a later provider step fails. Live text-AI behavior requires a verified subscription login/token and microphone test.

## Approved compact panels and Québec/Ontario taxes

Work option 4 from `mockups/work-no-number-review.html?revision=13`: round 40px line number, unit price / compact 80px quantity / amount, fixed two-line scrollable description, right vertical X/mic/AI rail, Add Line outside each card. Payments and notes are separate optional sections with matching thin section separators. Payment header and footer have 1px separators; the header has a 1px Amount/Date divider. Add Payment is inside the register. Notes use fixed 134px scrollable inputs with X then mic then AI in a right rail and Add Note outside. Fresh documents show only Add Note; removing the last note leaves zero entries. Existing nonempty legacy notes retain their exact text.

Appearance offers green, blue, orange and brown palettes, light/dark mode, and soft/strong container tint; choices persist locally. Form cards are tinted and input surfaces stay distinct. The live editor preview renders the actual generated Letter PDF pages, scaled to its own column and independent of editor height. The complete page stack has no internal scrollbar. A status explicitly identifies content requiring multiple pages. Native output still validates all fields and taxes; incomplete screen previews are marked provisional and unresolved tax totals are shown as pending. The Print button and Ctrl+P use page images from the exact in-memory customer document bytes at 300 dpi, with zero page margin and Letter page breaks, never the editable HTML approximation. Timeline lines and dots share one horizontal center. Visible tax choices are only Automatique, Ontario and Québec; internal legacy preservation remains a separate calculation state, displayed as Québec with explicit confirmation when needed before a new export. Fulfillment labels are Livraison et installation, Livraison seulement, and Retrait à l’atelier (Québec). Dropdowns are app-integrated keyboard-accessible menus layered over the authoritative select values; Escape closes only the open menu. Dropdown and quantity focus rings are inset. Payment dates use the same readonly text / tinted calendar segment as document dates.

`web/taxes.js` is the shared frontend calculation/resolution module for editor, saved/history draft previews, French/English PDFs and all print/email exports. `Draft.tax` is optional for legacy records; new drafts use version 1 / rule `qc-on-2026-10-01`. Fields: `schemaVersion`, `ruleVersion`, `fulfillment` (`installation`, `delivery`, `pickup`), `selection` (`auto`, `QC`, `ON`, `legacy`), `province` (`QC`, `ON`, null), `basis` (`shipTo`, `address`, `shop`, `manual`, `legacy`), `status` (`resolved`, `unresolved`, `unsupported`), and ordered `rates` (`code`, `rateMillionths`). Québec has GST 50000 and QST 99750 millionths; Ontario has HST 130000 millionths. Each tax rounds independently from integer-cent subtotal using fixed-point multiplication. Positive payments are deducted after tax. Ontario charges only HST/TVH, without a Québec QST tax row. PDF footers always show both company registration identifiers, including unresolved previews; Ontario uses the GST/HST label for the federal identifier. Registration identity does not resolve pending tax amounts.

Manual QC/ON wins until Automatique is selected. Automatic pickup uses the Québec shop. Otherwise a nonempty job/delivery address takes precedence; unknown job addresses do not fall back to billing. With no job address, billing is explicitly treated as the same job/delivery location. Explicit province names/codes at the address end are recognized; street names alone, ambiguous locations and city-only addresses do not select taxes. U.S./other recognized provinces remain outside automatic scope; separate custom invoices are required. Unsupported/unresolved drafts remain saveable, but PDF/print/email export is blocked pending a supported decision. Older drafts without `tax` retain original Québec totals; new output requires reviewing taxes when the old job location cannot clearly confirm Québec. Old archives and version identities are not rewritten on migration. All new archive entries include native-computed `taxTotals` (subtotal, tax-line, total, paid and balance cents), alongside the full Draft snapshot and immutable PDF bytes/hash. The native boundary validates the exact supported decision/rates and address resolution, rejects stale or invented snapshots, and rejects overflow before export.

## Business AI provider extension

`business` and `chatgpt` are the only provider selections. `businessConfigured` means a workspace token is stored; `chatgptConfigured` means granted personal plan credentials are stored. Neither flag proves completed inference. Personal login uses OpenAI's documented public-client flow, loopback callback, PKCE, state, nonce, signed identity validation, account matching, scope checks, DPAPI-protected credentials and serialized rotating refresh. Requests use the same subscription OAuth token for catalog and streamed Responses; incomplete/failed results are rejected. Disconnect clears local tokens and attempts remote revocation, reporting when revocation is unconfirmed. Business calls use a workspace-issued Codex access token and packaged official runtime. Z.ai/Claude have no fake login or Coding Plan bypass. Local Nemotron speech transcription remains free of remote API billing. Live subscription inference is a separate required acceptance gate.
