# Windows app integration contract

The selected `mockups/index.html` is the visual source. `app/web/` is the Vite input, `app/dist/` is its bundled output, and `app/src-tauri/` is the local Windows host. The app works without a server for document entry, storage, printing and PDF creation. French is the default language. Do not add customer facts or work details that Dad did not enter.

## Draft JSON

Use the mockup's field names: `id`, `kind` (`soumission` or `facture`), `date`, `validUntil`, `dueDate`, `client`, `shipTo`, `address`, `contact`, `email`, `project`, `notes`, `deposit`, and `items` (`description`, `quantity`, `price`). Date strings are `YYYY-MM-DD`; text fields remain strings. `englishCopy` holds the English project, notes, and line descriptions plus their exact French source texts; changing those French texts makes the English copy stale. It is saved and backed up with the same draft and never replaces French fields. The copy becomes reviewed when the user creates or prints its English PDF after viewing the preview. `invoiceNumber` is a displayed number supplied by the backend. `issuedNumber` is `null` until the first successful invoice export and stays fixed thereafter. The UI must never advance invoice numbering on draft save or repeated export. Print warns that it saves a PDF first; that first successful export issues an invoice number once. The backend is the authority for `invoiceNumber` and `issuedNumber`.

`payments` is an ordered array of `{ amount, date }` strings. A date may be empty or a valid `YYYY-MM-DD`; a filled payment must have a finite nonnegative amount. Empty rows are editable placeholders and do not print. Older drafts, recovery versions, and pending export snapshots without this array migrate their scalar `deposit` to one undated row; an explicit empty array remains empty. `deposit` remains a compatibility mirror; `payments` is authoritative when present. The sum uses cent rounding per row and is deducted after tax. Both customer languages preserve dates and amounts, show each positive row, the combined total, and the remaining balance; long lists flow onto additional Letter pages.

## Native commands

- `load_state() -> { current, records, nextInvoiceNumber, pdfDirectory, usingDefaultDirectory }`: load the current draft, searchable recent records, and current PDF destination. A record contains `{ id, draft, updatedAt, exports }`. The current draft is included in records. A first run returns a fresh quote draft and the default destination.
- `save_draft({ draft }) -> { current, records, nextInvoiceNumber }`: atomically persist the editable draft. The backend preserves any existing `issuedNumber`, and returns its authoritative invoice number. Trigger after a short typing pause and on field blur/structural changes.
- `new_draft({ kind }) -> { current, records, nextInvoiceNumber }`: save the previous current draft, create a blank draft of that kind, and make it current. This is the confirmed Reset/new-document action.
- `open_draft({ id }) -> { current, records, nextInvoiceNumber }`: make a recent draft current.
- `export_pdf({ draft, pdfBytes, expectedInvoiceNumber, language }) -> { path, filename, nameCollision, invoiceNumber, snapshot }`: validate and atomically write the completed PDF to the selected folder, initially `Documents/Entreprise/À classer/`, with an automatic safe name. `pdfBytes` is an array of unsigned bytes. For invoices, reject stale `expectedInvoiceNumber`; issue the number only after a successful file write, then keep it on all later exports of that document. Quotes have no public number. Repeated exports of one document retain its number and use a collision-safe file path; `nameCollision` tells the UI when the original filename was already occupied. Return a new snapshot. `language` is `fr` or `en`. If a custom folder disappears, report an error and do not issue a number or silently redirect output.
- `restore_previous({ id }) -> { current, records, nextInvoiceNumber }`: restore a recoverable earlier version of a record without changing an already issued invoice number.
- `set_next_invoice_number({ number, allowReuse }) -> { current, records, nextInvoiceNumber }`: change the future automatic number when the selected number is at or above the current automatic number. An older number requires a visible warning and `allowReuse: true`; assign that number to the current unissued invoice only. If the current invoice was already issued, create a new blank invoice with the selected number. Preserve issued invoices and the automatic sequence; never overwrite existing PDFs. Reject nonpositive or out-of-range values.
- `set_output_directory({ path }) -> { current, records, nextInvoiceNumber, pdfDirectory, usingDefaultDirectory }`: choose an existing writable absolute directory for future PDFs, or pass `null` to restore the default. Persist the choice without moving older PDFs. A pending invoice export must be reconciled in its original directory before changing the destination.
- `get_ai_settings()`, `set_ai_provider({ provider })`, and `set_ai_key({ provider, key })`: select OpenAI or Z.ai for text processing and store the provider's general API key in Windows Credential Manager. `key: null` removes a key. Return only configured flags, never the credential itself. The chosen provider name is saved with local app settings; the key is not.
- `ai_translate_english({ draft }) -> { project, notes, descriptions }`: use the selected provider to translate only customer-entered free text. Require that the submitted draft matches the saved document; reject missing keys, provider errors, malformed responses, and changed line counts without replacing French data. The UI saves the translated copy with the French draft and shows it in the English preview. Creating or printing the English PDF confirms that copy.
- `start_local_asr() -> websocketUrl`: start the bundled Nemotron 3.5 CPU speech engine on an authenticated loopback port. The WebView streams 16 kHz PCM to it, renders partial transcript events, and commits final utterances. Audio is not uploaded to OpenAI or Z.ai.
- `ai_rewrite_line({ source, style, variation }) -> string`: request French prose or bullet text for a single line. The UI shows a proposal and changes the original line only after acceptance.
- `ai_extract_document({ transcript }) -> VoiceUpdate`: extract optional fields and ordered work items from cumulative recognized speech. The frontend validates dates and amounts, retains existing values, and saves accepted field updates as an ordinary draft. This command cannot export a PDF or issue a number.

All commands return clear errors without replacing the last good saved data. The backend owns the local data file and a separate recoverable backup. Do not put secrets or customer data in the repository.

## UI and PDF module

`app/web/pdf.js` exports `createPdf(draft, { invoiceNumber, language }) -> Promise<Uint8Array>`. It renders a US Letter customer PDF with company logo, real-text company name/address/phone, item descriptions with wrapping and multiple pages as needed, totals, deposit if present, and the confirmed TPS/TVQ registration numbers. It must encode the supplied client data without HTML execution. English output takes a reviewed overlay; the renderer does not translate. The backend verifies current review before saving an English PDF. `app/web/app.js` imports this function and invokes `export_pdf` only after field validation. Print clearly warns that a PDF will be saved first, then displays only the customer document.

The packaged UI should keep the mockup's single selected design, including the two large document choices, side-by-side editor and large preview, light/dark modes, date picker, multiline work lines, line mic/AI icons, recent documents, Undo, and validation. Manual French entry and export remain fully available offline. Translation requires an explicitly chosen provider; English PDF creation requires the user to review its preview, then confirm through Create PDF or Print. Work-line dictation and rewriting are reviewable proposals. Document dictation shows interim words locally, then passes completed utterances to the selected text AI to update fields, preserves existing manually entered values, and clearly asks for review before PDF export. Recognized words must remain visible for retry or copying if a later provider step fails. Live text-AI behavior still requires a valid general key and microphone test.
